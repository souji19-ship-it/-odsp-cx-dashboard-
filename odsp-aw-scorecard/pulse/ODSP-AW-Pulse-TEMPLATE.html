This week's 2P story

ODSP is already a meaningful substrate for M365 agents calling OneDrive and SharePoint, before the architecture converges on direct MCP and Work IQ-routed MCP. The latest complete week shows broad Cowork reach, growing Cowork execution volume, and a Copilot Studio / Dracarys mix shift toward more ODSP tool calls and substantially more knowledge grounding.

Growth × engagement

Execution grew across both workloads, with different reach patterns

Cowork users were flat, while ODSP-backed tasks increased +8% and tool calls increased +6%. Copilot Studio / Dracarys matched users increased +18%, tasks +30%, tool calls +14% and ODSP knowledge searches +47%.

Why it matters: growth was broad but uneven across metrics. Scenario mix, repeat use and completed outcomes should be measured alongside active identities so higher volume can be connected to customer value.

Breadth × depth

Cowork has broad reach; Copilot Studio / Dracarys knowledge is the deepest contribution

ODSP reached 48% of Cowork users and 63% of Cowork tenants. It contributed 24% of Cowork tasks. In Copilot Studio / Dracarys, ODSP reached 31% of users and powered 36% of knowledge searches.

Why it matters: reach is already material, but contribution depth varies by workload. The next goal is to turn broad access into repeatable customer outcomes rather than optimize a single volume metric.

Reliability

ODSP tool reliability remained high across both 2P workloads

Cowork ODSP tool success was 96%, a movement of -0.7 pp week over week. Copilot Studio / Dracarys ODSP service success was 92%, a movement of +0.4 pp.

Why it matters: the reliability baseline is high enough to shift focus toward outcome depth, while continuing to segment failures by service-owned versus caller-owned causes.

Architecture runway

Today's bespoke integrations establish the pre-MCP baseline

The current Cowork and Copilot Studio / Dracarys measurements describe bespoke Graph API and connector paths. Direct SharePoint MCP and Work IQ-routed SharePoint/OneDrive MCP require explicit route attribution before their adoption, engagement and reliability can be compared.

Why it matters: this baseline makes the upcoming transition measurable. Route-level telemetry must distinguish Graph API, direct MCP and Work IQ-routed MCP without inferring architecture from tool names.

Leadership watch

Copilot Studio / Dracarys growth was broad; Knowledge Search led

Matched Copilot Studio / Dracarys users moved +18% and tasks moved +30%, while tool calls moved +14% and knowledge searches moved +47%. The Aug 9–15 Cowork fixed-week owner tool-call denominator is unavailable; the separate 14% daily penetration estimator and broader server aggregate are different lenses and are not substituted.

Why it matters: the pace of growth differs across reach, execution and grounding. The actionable question is which scenarios and agents produced the higher event intensity and whether they completed valuable outcomes.

Overall: ODSP's 2P footprint combines broad Cowork reach, increasing Cowork execution, growing Copilot Studio / Dracarys knowledge grounding and high tool reliability. Focus is converting this footprint into repeatable high-value scenarios while instrumenting the migration from bespoke Graph paths to direct MCP and Work IQ-routed MCP.

Methodology

Adoption
Active Users: Count of unique 2P agent users who used at least one ODSP tool.
Active Tenants: Count of unique 2P agent tenants where at least one ODSP tool was used.
Active Agents: Count of unique 2P agents that used at least one ODSP tool.
Engagement
Tasks: Count of 2P agent tasks in which at least one ODSP tool contributed to task execution.
Tool Calls: Count of 2P agent tool calls that leveraged an ODSP tool.
Knowledge Searches: Count of 2P agent knowledge searches that leveraged an ODSP knowledge source.
Reliability
Tool Success Rate: Percentage of ODSP tool calls that completed successfully.
